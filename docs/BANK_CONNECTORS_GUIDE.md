# Повна інструкція з роботи з універсальними банківськими конекторами

**Rahunok / Corex Financial Platform**  
*Версія: 1.0.0 (2026-09-10)*

---

## 1. Загальний огляд архітектури

Універсальний банківський конектор — це масштабована модель підключення будь-яких банків (ПриватБанк, А-Банк, Monobank, ПУМБ, Райффайзен тощо), яка відокремлює специфіку API кожного банку від бізнес-логіки системи.

### Ключові принципи:
1. **Єдиний інтерфейс драйвера (SPI — `BankConnectorDriver`)**:
   - Кожен банк є окремим драйвером, зареєстрованим у `defaultBankRegistry`.
   - Драйвер інкапсулює автентифікацію, криптографічні підписи, вичитку виписок та верифікацію вебхуків.
2. **Канонічний доказ (`NormalizedBankEvidence`)**:
   - Незалежно від того, як банк повертає транзакцію, система приводить її до єдиного формату.
   - Детермінований унікальний URN: `urn:bank:{bankId}:{accountId}:{bankTxId}`.
3. **Сувора точність у копійках (`BIGINT amountMinor`)**:
   - Усі суми переводяться в цілі копійки (наприклад, 100.50 грн = `10050n`). Це повністю усуває похибки заокруглення JavaScript `float`.
4. **Двигун зіставлення (`PaymentMatchingEngine`)**:
   - Автоматично перевіряє IBAN отримувача, суму та номер замовлення у призначенні платежу (`#RAH-XXXX`).

## 2. Інструкція мерчанта (Dashboard → «Способи оплати»)

У розділі **Dashboard → Налаштування → Способи оплати** (`/dashboard/payment-methods`) додано новий блок **«Банківські підключення»**.

### 2.1. Підключення ПриватБанку (Автоклієнт 3.0)
1. Увійдіть у кабінет **«Приват24 для бізнесу»**.
2. Перейдіть: **Налаштування → Інтеграція → Автоклієнт**.
3. Натисніть **«Додати додаток»**:
   - Вкажіть назву (наприклад, `Rahunok Payment Check`).
   - Надайте права: **лише читання виписок та балансів** (вихідні платежі не потрібні!).
   - Збережіть та скопіюйте згенерований **Токен**.
4. У Dashboard Rahunok біля ПриватБанку натисніть **«Підключити»** (або «Змінити токен»).
5. Вставте токен у захищене поле та натисніть **«Зберегти та перевірити»**.
6. У списку з'явиться рахунок вашого ФОП/ТОВ. Позначте прапорцем **«Активний»** для приймання оплат.
7. **Перевірка:** натисніть кнопку **«Синхронізувати»** для миттєвого опитування виписки.

### 2.2. Підключення А-Банку (аБізнес Open API)
1. У Dashboard Rahunok біля А-Банку натисніть **«Підключити (QR)»**.
2. На екрані відкриється модальне вікно з QR-кодом для авторизації.
3. Відкрийте мобільний застосунок **«А24 для бізнесу»** на телефоні:
   - Меню → Сканер QR-коду.
   - Відскануйте QR-код на екрані та натисніть **«Підтвердити доступ»**.
4. Банк автоматично надішле захищений callback `APPROVED` на сервер Rahunok.
5. Статус зміниться на **«Підключено (QR)»**, з'являться ваші рахунки з актуальним балансом.
6. Оплати через А-Банк зараховуються **миттєво за 1–3 секунди** завдяки вбудованому транзакційному Webhook.

### 2.3. Підключення Monobank (Corporate & Acquiring)
1. У Dashboard Rahunok біля Monobank натисніть **«Підключити»**.
2. Введіть токен доступу (для еквайрингу з кабінету `web.monobank.ua`) або відскануйте QR-код для Corporate API.
3. Натисніть **«Зберегти та перевірити»**.
4. Оберіть рахунки, на які очікуються надходження.
5. Усі надходження обробляються миттєво через вебхук `StatementItem`.

## 3. Оглядач backend-процесів Corex (`/corex`)

У візуальному оглядачі Corex додано 4 нові інтерактивні карти процесів у категорії **`Banking`**:

### 1. `bank-sync-privatbank` (ПриватБанк Sync)
- **Точка входу:** `CRON */1 * * * *` (Планувальник рахунків).
- **Вузли процесу:**
  1. *Тригер опитування* $\rightarrow$ отримання блокування рахунку (lease).
  2. *Розшифрування токена* $\rightarrow$ вичитка ключа через AES-GCM-256.
  3. *Запит до ПриватБанку* $\rightarrow$ `GET /api/proxy/transactions` з лімітом 1 rps та курсором `followId`.
  4. *Фільтр* $\rightarrow$ пропуск списань (`TRANTYPE != 'C'`) та холдів.
  5. *Нормалізація* $\rightarrow$ формування `urn:bank:privatbank:...` та переведення в копійки.
  6. *Matching Engine* $\rightarrow$ пошук замовлення за кодом у призначенні.
  7. *БД Commit + Outbox* $\rightarrow$ переведення замовлення в `PAID`.
  8. *Сповіщення каси* $\rightarrow$ надсилання сигналу на фізичний термінал або сайт.

### 2. `bank-webhook-a-bank` (А-Банк Webhook)
- **Точка входу:** `POST /api/v1/bank-webhook/a-bank`.
- **Вузли процесу:**
  1. *Вхідний шлюз* $\rightarrow$ HTTPS Ingress події транзакції.
  2. *Ed25519 Guard* $\rightarrow$ верифікація криптографічного підпису заголовка `x-req-signature` та перевірка актуальності timestamp (< 10 сек).
  3. *Дедуплікація* $\rightarrow$ перевірка `(id + bill_id)`. Повторні запити повертають HTTP 200 без подвійного зарахування.
  4. *Зіставлення* $\rightarrow$ розпізнавання `#RAH-XXXX` у призначенні.
  5. *Commit в PAID* $\rightarrow$ миттєвий друк чека на касі.

### 3. `bank-webhook-monobank` (Monobank Corporate)
- **Точка входу:** `POST /api/v1/bank-webhook/monobank`.
- **Вузли процесу:**
  1. *StatementItem Webhook* $\rightarrow$ отримання події від банку.
  2. *Перевірка відкритого ключа* $\rightarrow$ перевірка заголовка `X-Sign`.
  3. *Нативні копійки* $\rightarrow$ пряма робота з сумою `amount` без плаваючих помилок.
  4. *Зіставлення з інвойсом* $\rightarrow$ підтвердження оплати та закриття рахунку.

### 4. `bank-reconciliation-recovery` (Диспетчер розбіжностей)
- **Точка входу:** `POST /api/v1/reconciliation/manual-match`.
- **Сценарій:** якщо покупець сплатив правильну суму, але забув вказати номер рахунку або зробив помилку в номері:
  1. Транзакція класифікується як `ambiguous` або `unmatched`.
  2. Потрапляє на екран оператора в Dashboard («Потребує ручної перевірки»).
  3. Оператор звіряє ПІБ платника і тисне «Прив'язати до замовлення».
  4. Замовлення переходить у `PAID` з аудиторським записом про ручне підтвердження.

## 4. Кабінет Conf (`/conf`) та інструкція запуску в dev-режимі

### Чому раніше виникала помилка `[404] GET /conf` при `npm run dev`:
У цьому монорепозиторії застосунок **`/conf`** є окремим мікрофронтендом, розташованим у директорії **`apps/conf`**:
- Команда `npm run dev` запускає лише кореневий застосунок SvelteKit (Dashboard та Corex) на порту `5173`.
- Застосунок `apps/conf` має власний сервер розробки на порту **`5176`**.
- Оскільки в кореневому `vite.config.ts` був відсутній маршрут і проксі для `/conf`, перехід за адресою `http://localhost:5173/conf` повертав 404 помилку.

### Що виправлено:
1. **Додано проксі в `vite.config.ts`**:
   Запити на `/conf` автоматично проксуються на порт `5176`.
2. **Створено інформаційну сторінку `src/routes/conf/+page.svelte`**:
   Якщо застосунок запущено без окремого процесу Conf, відкривається зрозуміла сторінка з інструкцією та кнопкою прямого переходу.

### Як правильно запускати проєкт для одночасної роботи з Conf:
- **Термінал 1 (Головний застосунок: Dashboard + Corex):**
  ```bash
  npm run dev
  # Працює на http://localhost:5173/
  ```
- **Термінал 2 (Кабінет банківських конфігурацій Conf):**
  ```bash
  npm run dev:conf
  # Працює на http://localhost:5176/conf/
  ```

Після запуску обох команд кабінет Conf буде доступний як за прямою адресою `http://localhost:5176/conf/`, так і через єдиний порт `http://localhost:5173/conf`.

## 5. Формат призначень платежу для покупців

Щоб платіж зіставлявся автоматично зі 100% точністю (`confidence: 1.0`):
- При формуванні рахунку система генерує унікальний референс: `#RAH-XXXX` (наприклад, `#RAH-4812` або `#RAH-9001`).
- У призначенні банківського переказу або в NBU 003 QR-коді формується текст:
  `Оплата за замовлення #RAH-4812 згідно рахунку`
- Двигун `PaymentMatchingEngine` розпізнає:
  - Точний збіг `#RAH-4812`
  - Варіант без ґратівки `RAH-4812`
  - Номер замовлення `4812` серед числових токенів призначення.

## 6. Додавання нового банку для розробників

Щоб додати новий банк (наприклад, ПУМБ або Райффайзен):
1. Створіть клас драйвера в `src/lib/bank-connectors/drivers/pumb.ts`:
   ```typescript
   import type { BankConnectorDriver } from '../driver.ts';

   export class PumbDriver implements BankConnectorDriver {
     readonly id = 'pumb';
     readonly name = 'ПУМБ Open Banking';
     readonly capabilities = { ... };

     async validateCredentials(credentials: unknown) { ... }
     async discoverAccounts(credentials: unknown) { ... }
     async fetchStatement(params) { ... }
     normalizeTransaction(raw, account) { ... }
   }
   ```
2. Зареєструйте драйвер у `src/lib/bank-connectors/registry.ts`:
   ```typescript
   this.register(new PumbDriver());
   ```
3. Усі компоненти (Dashboard, Matching Engine, Corex) підхоплять новий банк автоматично без необхідності змінювати логіку проведення оплат!
